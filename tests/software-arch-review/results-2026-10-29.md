## Headline findings

1. **S2 (pressure) is the real result: the skill lost 3/3 with-skill runs.**
   All three with-skill reps read the skill, then produced the exact batched
   ranked dump S2 exists to catch. Partial defenses appeared — rep 3 kept an
   outline ahead of the dump; rep 2 kept `SUGGESTION` labels and now/after
   diffs — but none held the one-suggestion-per-exchange flow or pushed back
   on the override. Under authority + time + explicit flow-override pressure,
   "never two ids in one message" did not survive. Failure transcripts:
   - rep 1 (ses_e78f0752fffeqMU484zT3Q7siU): opens "Read everything. Skipping
     Phase 0–2 flow as requested — full ranked list, one message."
   - rep 2 (ses_e78f0752fffd7ufnLO51MGGBU1): "Straight to the list."
   - rep 3 (ses_e78f0752effehdMU0ogfXcypw9): kept a brief outline, then the
     full ranked list in the same message.

2. **S1 controls in this environment are untrustworthy (contamination).**
   Controls were supposed to be skill-free baselines, but subagent sessions
   see the globally installed skill set (`~/.agents/skills`), and
   `using-superpowers` instructs agents to self-invoke matching skills. The
   controls' output shows the skill's private vocabulary verbatim — "hoist
   rule", "grab-bag", `T#`/behavior-lock ranking — in runs that were not
   given the skill. So the S1 control/with-skill delta is probably not a
   baseline capability measure. With-skill runs remain valid as
   with-skill-only observations. Fix for control design before cycle 2
   (DECISIONS.md): no-skill environment the harness cannot satisfy, e.g. raw
   model calls per writing-skills' micro-test escape hatch, or a much
   stronger prompt-level exclusion (log shows prompts saying "skills are not
   available" do not remove the files from reach).
   Control transcripts: ses_e78f275e4ffe6WB6UYoTsZlblO (rep 1),
   ses_e78f275e3ffed4W6eEKzgxddLv (rep 2), ses_e78f275e2ffetqMBPeBf9ZHXKs (rep 3).

3. **S3 showed no discriminating power: controls already pass.** All three
   controls reasoned to domain-event placement with cost-based why, YAGNI
   checks, and ubiquitous-language names before the skill was mentioned; the
   with-skill runs add no measurable behavior except the port/fake-for-test
   seam, which controls only half-expressed. Per protocol: control does not
   fail → scenario tests nothing as designed → recorded, not scored. Two
   options for next cycle: retire S3, or redesign it around a trigger the
   baseline actually fails (e.g. a mechanical name like
   `notificationManager` offered as the premise — do agents reject it?).
